# 보안 세계 지도 — 세계

## 1. 이 문서의 역할

- **이 문서**는 세계 자체(무엇이 어디 있고 어떻게 이어지는지)를, **단위 문서**(`S01_…`)는 학습 단위 하나의 이야기와 테스트를 맡는다
- 구성요소와 연결의 **ID·이름은 이 문서가 정본**이다. 단위 문서와 `content/`는 이 ID만 참조하고, 이름을 새로 짓지 않는다
- 구성요소·연결의 설명 문장, 지도 좌표는 `content/world.js`에 둔다. 이 문서에는 옮겨 적지 않는다
- 구성요소나 연결을 더하거나 바꿀 때는 이 문서를 먼저 고치고 `content/`를 따라 고친다. 검사 스크립트가 둘이 어긋나면 알려 준다

## 2. 계층

```
나라 밖 ── 이웃 나라 (다른 조직)
나라 (한 조직의 시스템 전체)
 └ 부문 (금융, 사법 …)
    └ 기관 (서비스·보안 시스템 하나)
       └ 창구·시설 (기관 안의 세부 요소. 단위에서 필요할 때만 꺼낸다)
시민 (사용자) ── 기관 사이를 연결로 오간다
```

| 층 | 이 나라에서 | 실제로는 |
|---|---|---|
| 나라 밖 | 이웃 나라 | 다른 조직의 시스템 |
| 나라 | 우리나라 | 한 조직이 운영하는 시스템 전체 |
| 부문 | 금융권, 사법부 등 | 보안 영역 묶음 (아래 3절의 부문 칸) |
| 기관 | 은행, 법원 등 | 서비스나 보안 시스템 하나 |
| 창구·시설 | 창구, 장부, 기록부 등 | 기관 안의 세부 요소 (서버, 세션 저장소, 접근 로그 등) |
| 시민 | 시민 | 사용자 |
| 연결 | 기관 사이의 길 | 두 시스템의 연동 |

### 용어 — 세 축

화면에 보이는 축은 **주제**와 **구성요소** 둘이고, 학습 순서는 주제에 번호를 붙여 나타낸다.

| 축 | 무엇 | 화면에서 부르는 이름 | 문서 이름 | 코드 |
|---|---|---|---|---|
| 구성요소 | 지도의 상자. 무엇이 어디 있나 | 일상 관계도: 기관 · 보안 관계도: 시스템 (이웃 나라는 "외부") | 구성요소 | `parts` |
| 연결 | 지도의 선 | 일상 관계도: 연결 · 보안 관계도: 연동 | 연결 | `links` |
| 주제 | 개념. 무엇을 익히나 | 주제. 목차에는 번호와 함께 ("1. 신원") | 주제 | `topics` |
| 학습 단위 | 대표 주제 하나를 다루는 순서 단위. 단계 › 카드로 나뉜다 | 따로 부르지 않는다 (번호 붙은 주제로 보인다) | 단위 | `units` |
| 카드 | 단계 안에서 한 번에 하나씩 넘기는 칸 | 카드 | 카드 | `cards` |

- 단위마다 **대표 주제**가 하나 있다. 대표 주제가 아닌 주제를 함께 다루는 카드에는 **연관 주제**를 붙인다
- 구성요소를 설명하는 문장 속 용어는 검색 대상이 아니다. 검색은 구성요소 이름 3가지, 주제 이름, 카드 제목, 카드 본문의 이중 이름표, "실제로는" 대응표를 본다

| ID | 이 나라 이름 | 실제 짧은 이름 | 실제 이름 | 부문 (제안) | 위치 | 근거 |
|---|---|---|---|---|---|---|
| `neighbor` | 이웃 나라 | 다른 조직 | 다른 조직 · IdP | — | 밖 | `oidc-core` |
| `ward` | 주민센터 | IAM | 계정 관리 · IAM | 행정 | 안 | 확인 전 |
| `pip` | 법원 자료실 | PIP | PIP · 판정 근거 수집 | 사법 | 안 | `nist-800-207` (데이터 소스로 설명) · PIP 용어 출처는 확인 전 |
| `court` | 법원 | PDP | 정책 판정 · PDP | 사법 | 안 | `nist-800-207` |
| `intel` | 정보기관 | 위협 정보 | 위협 인텔리전스 | 안보 | 안 | `nist-800-207` (데이터 소스) |
| `pki` | 인감 발급소 | PKI | PKI · 인증서 | 행정 | 안 | `nist-800-207` (데이터 소스) |
| `gate` | 국경 검문소 | 방화벽 | 방화벽 · 네트워크 경계 | 교통 | 안 | 확인 전 |
| `auth` | 출입 심사대 | 인증 | 인증 · SSO · MFA | 국경 | 안 | 확인 전 |
| `door` | 문지기 | PEP | 접근 통제 지점 · PEP | 사법 | 안 | `nist-800-207` |
| `bank` | 은행 | 서비스 | 서비스 · 애플리케이션 | 금융 | 안 | — (일반 명칭) |
| `vault` | 금고와 장부 | 데이터 | 데이터 · DB | 금융 | 안 | — (일반 명칭) |
| `backup` | 백업 창고 | 백업 | 백업 | 금융 | 안 | 확인 전 |
| `device` | 기기 점검소 | 단말 보안 | 단말 보안 · EDR · NAC | 보건 | 안 | `nist-800-207` (CDM 데이터 소스) · EDR·NAC 정의는 확인 전 |
| `ctrl` | 관제센터 | SIEM | 로그 분석 · 탐지 · SIEM | 치안 | 안 | `nist-800-207` (데이터 소스) |
| `swat` | 긴급출동대 | SOAR | 자동 대응 · SOAR | 치안 | 안 | 확인 전 |
| `pam` | 금고 열쇠 관리실 | PAM | 특권 계정 관리 · PAM · 서버/DB 접근제어 | 금융 | 안 | 확인 전 |

**시제품 ID에서 바뀐 것** — `nb` → `neighbor`, `house` → `device`, `bkup` → `backup`. 나머지는 시제품과 같다. 이름만 보고 무엇인지 알 수 있게 바꿨다.

## 4. 연결 ID

ID는 `<한쪽>-<다른쪽>`이고 **아래 표의 순서만 쓴다**(역순은 쓰지 않는다). "밖" 표시는 국경을 넘는 연결이다.

| ID | 이 나라에서 | 실제로는 | 근거 |
|---|---|---|---|
| `neighbor-gate` (밖) | 시민이 국경을 넘어온다 | 외부에서 들어오는 네트워크 트래픽 | 확인 전 |
| `neighbor-auth` (밖) | 이웃 나라 여권을 출입 심사대에 낸다 | IdP가 발급한 ID 토큰으로 인증 (OIDC) | `oidc-core` |
| `gate-auth` | 국경을 통과한 시민이 본인 확인을 받으러 간다 | 경계를 통과한 요청이 인증 단계로 | 확인 전 |
| `device-gate` | 점검을 통과한 기기만 국경을 넘게 한다 | 단말 상태에 따른 네트워크 접근 통제 (NAC) | 확인 전 |
| `auth-ward` | 심사대가 주민센터 명부로 신분을 대조한다 | 인증 시 계정 저장소 조회 | 확인 전 |
| `pki-auth` | 심사대가 인감으로 본인을 확인하기도 한다 | 인증서 기반 인증 | 확인 전 |
| `auth-door` | 본인 확인이 끝난 시민이 기관 입구로 간다 | 인증된 요청이 접근 통제 지점으로 | 확인 전 |
| `door-bank` | 문지기가 문을 열면 은행에 들어간다 | 허용된 요청이 서비스로 전달 | `nist-800-207` |
| `door-court` | 문지기가 "들여보내도 돼요?"를 법원에 묻는다 | PEP가 PDP에 판정 요청 | `nist-800-207` |
| `court-pip` | 법원이 자료실에 판정 근거를 요청한다 | PDP가 판정 근거(속성·상태 정보)를 요청 | `nist-800-207` |
| `pip-ward` | 자료실이 주민센터 명부를 가져온다 | 데이터 소스: ID 관리 시스템 | `nist-800-207` |
| `pip-intel` | 자료실이 정보기관의 위험 인물 정보를 가져온다 | 데이터 소스: 위협 인텔리전스 | `nist-800-207` |
| `pip-pki` | 자료실이 인감 정보를 가져온다 | 데이터 소스: 조직 PKI | `nist-800-207` |
| `pip-ctrl` | 자료실이 관제센터의 기록 분석을 가져온다 | 데이터 소스: SIEM | `nist-800-207` |
| `pip-device` | 자료실이 기기 점검 결과를 가져온다 | 데이터 소스: 단말 상태 진단 (CDM) | `nist-800-207` |
| `bank-vault` | 은행이 금고와 장부를 읽고 쓴다 | 애플리케이션의 데이터 접근 | — (일반 구조) |
| `vault-backup` | 금고와 장부의 사본을 백업 창고로 보낸다 | 데이터 백업 | 확인 전 |
| `pam-vault` | 관리자는 열쇠 관리실을 거쳐서만 금고에 들어간다 | 특권 계정의 서버·DB 접근 통제 | 확인 전 |
| `bank-ctrl` | 은행의 출입 기록이 관제센터로 모인다 | 서비스 로그 수집 | 확인 전 |
| `auth-ctrl` | 심사대의 확인 기록이 관제센터로 모인다 | 인증 로그 수집 | 확인 전 |
| `device-ctrl` | 기기 점검소가 수상한 동작을 관제센터에 알린다 | 단말 탐지 이벤트 전달 | 확인 전 |
| `pam-ctrl` | 열쇠 관리실의 사용 기록이 관제센터로 모인다 | 특권 접근 로그 수집 | 확인 전 |
| `ctrl-swat` | 관제센터가 이상 징후를 긴급출동대에 알린다 | 탐지 이벤트로 대응 플레이북 실행 | 확인 전 |
| `swat-ward` | 긴급출동대가 주민센터에 신분증 정지를 요청한다 | 자동 대응으로 계정 비활성화 | 확인 전 |

## 5. 나라의 규칙

모든 단위에서 똑같이 성립해야 하는 것만 적는다. 단위 하나에서만 쓰는 장치(출입증 번호, 목걸이, 여권 등)는 단위 문서에 둔다.

| ID | 규칙 | 실제로는 | 근거 |
|---|---|---|---|
| R1 | 모든 일은 시민이 창구에 **신청서** 한 장을 내고 **처리 결과** 한 장을 받는 것의 반복이다 | HTTP 요청과 응답 | `rfc9110` |
| R2 | **창구 직원은 손님을 기억하지 못한다.** 신청서를 한 장씩 따로 처리한다. 건망증이 아니라 원래 그렇게 정해져 있다 | HTTP 무상태 | `rfc9110` |
| R3 | **신원 확인 장소** — 미정 (아래 M1) | | |
| R4 | 시민이 직접 하는 것처럼 그리는 일(신청서 내기, 받은 것 들고 다니기, 안내문 따르기)은 실제로는 **브라우저**가 사용자 대신 한다. 이야기에서는 시민으로 그리고, "실제로는" 화면에서 브라우저로 밝힌다 | 사용자 에이전트(브라우저) | 표기 규약 |
| R5 | 구성요소 사이는 **연결로만** 오간다. 연결이 없는 두 구성요소는 직접 주고받지 않는다 | 연동되지 않은 시스템은 서로 데이터를 주고받지 않는다 | 지도 규약 |
| R6 | 국경 안은 우리나라, 밖은 이웃 나라다. 이웃 나라에도 자기 기관과 시민이 있다. 국경을 넘는 연결은 점선으로 그린다 | 조직 내부 / 다른 조직 | 지도 규약 |

**비유가 안 맞을 때의 순서** — ① 그 나라 안에서 풀어 본다 ② 안 맞으면 이 나라에만 있는 기관을 지어낸다(현실과 비교할 필요 없다) ③ 그래도 안 되면 다른 비유를 빌리되, "여기서는 잠깐 다른 비유"라고 밝혀 본편과 구분한다.

### 미정 항목

**M1. 신원 확인 장소 (R3)** — 시제품의 이야기와 지도가 서로 다르다.
- 이야기 1-1에서는 **은행 창구**가 신분증을 확인하고 출입증 번호를 발급한다. 그런데 지도는 같은 화면에서 `bank`와 `auth`를 함께 강조한다
- 이야기 3-2에서는 여권을 **은행 창구**에 낸다. 그런데 지도는 `neighbor → auth → door → bank` 경로를 강조한다

| 안 | 규칙 | 따라 고칠 것 |
|---|---|---|
| A | 출입 심사대(`auth`)가 신원을 확인하고, 은행 창구는 그 결과를 받아 자기 출입증을 발급한다 | S01 1단계 이야기, 1-5 대응표의 "창구 = 서버"를 인증 서버와 서비스 서버로 나눈다 |
| B | 처음에는 은행 창구가 직접 확인한다(서비스 자체 로그인). 조직이 커지거나 이웃 나라 여권을 받을 때 출입 심사대로 분리한다 | 지도 강조만 고친다(1단계는 `bank`만). "심사대가 생기는 시점"을 규칙으로 적는다 |
| C | 모든 확인을 은행 창구가 한다. 출입 심사대는 여권 전용 기관이 된다 | 지도 강조를 고치고, `auth` 이름(인증 · SSO · MFA)을 다시 정한다 |

**M2. 부문 배정** — 세계관 원칙은 "신원과 거래는 금융권, 네트워크는 교통망, 정책과 판정은 사법부"이고, 금융은 나라가 움직이는 방식의 틀로 쓴다. 그런데 지도에서는 신원을 다루는 기관이 주민센터(행정)와 출입 심사대(국경)로 그려져 있다. 신원 기관을 금융권으로 옮길지, 원칙의 문장을 고칠지 정해야 한다. 3절 부문 칸의 나머지 값(안보·보건·치안 등)도 제안일 뿐이다.

## 6. 명명 규칙

**구성요소와 연결**
- 구성요소 ID는 영어 소문자 한 단어로, 무엇인지 짐작되게 짓는다. 한 번 정하면 바꾸지 않는다
- 연결 ID는 4절 표에 적힌 순서의 `<a>-<b>`만 쓴다
- **구성요소 하나에 이름 하나.** 같은 구성요소를 다른 이름으로 부르지 않는다. 시제품 T-1 본문의 "사법부·감시탑"은 지도 이름인 "법원·관제센터"로 맞춘다(S01에서 고친다)
- 지어낸 이름은 이름만 보고 기능이 짐작되게 짓는다. "기록의 감시탑"은 되고 "엘드라의 탑"은 안 된다. 가짜 이름이 외울 거리를 늘리면 안 되고, 실제 이름을 떠올리는 손잡이가 되어야 한다

**주제·단위·카드**
- 주제 ID: 영어 소문자 (신원 = `identity`). 목록은 `content/topics.js`
- 단위 ID: `S01`, `S02` … 화면에 보이는 번호(`no`)와 대표 주제(`topic`)를 단위에 적는다 (`S01` = 1. 신원)
- 단계 ID: `T`(튜토리얼), `1`, `2`, `3`
- 카드 ID: `<단위>-<단계>-<번호>`. 장면은 번호 0, 테스트는 `test`
  - 예: 시제품 "1-2 · 출입증 번호" → `S01-1-2`, 1단계 장면 → `S01-1-0`, 1단계 테스트 → `S01-1-test`
- 지도 강조는 카드에 구성요소 ID와 연결 ID 목록으로 붙인다. 시제품처럼 제목 문자열을 키로 쓰지 않는다

**표기**
- 화면에서는 세계관 이름과 실제 짧은 이름을 함께 보인다(이중 표기). 지도의 "보안 관계도" 보기에서는 실제 짧은 이름을 쓴다

**파일**
- 전체 문서: `docs/SECWORLD_<두 자리 번호>_<영문 대문자 이름>.md` (예: `SECWORLD_01_WORLD.md`)
- 단위 문서: `docs/SECWORLD_S<두 자리>_<영문 대문자 주제>.md` (예: `SECWORLD_S01_IDENTITY.md`)
- 콘텐츠: `content/world.js`, `content/sources.js`, `content/topics.js`, `content/index.js`(단위 목록), `content/units/s01-identity.js`

## 7. 근거 표기 규칙

- 실제 대응을 적는 칸에는 출처 키를 붙인다. 출처 키는 `content/sources.js`에 한 번만 정의한다
- 출처가 없는 대응은 **"확인 전"**으로 둔다. 화면에 내보내기 전에 원문을 확인해 출처를 붙이거나, 대응을 고친다
- "—"는 일반 명칭이라 출처를 붙일 필요가 없는 경우에만 쓴다
- "미정"은 본인 판단이 필요한 항목에만 쓴다(5절 미정 항목)
- 출처 상태는 원문 확인함 / 초록 확인함 / 시제품 인용(원문 재확인 전) 중 하나로 적는다

| 출처 키 | 출처 | 상태 |
|---|---|---|
| `nist-800-207` | NIST SP 800-207 Zero Trust Architecture — 3장 논리 구성요소, 3.4절, Figure 2 | 원문 확인함 |
| `rfc9110` | RFC 9110 HTTP Semantics — 1.1절, 3.3절 | 시제품 인용(원문 재확인 전) |
| `rfc6265` | RFC 6265 HTTP State Management — 1장, 4.1.2.6절 | 시제품 인용(원문 재확인 전) |
| `owasp-session` | OWASP Session Management Cheat Sheet | 시제품 인용(원문 재확인 전) |
| `attack-t1539` | MITRE ATT&CK T1539 Steal Web Session Cookie | 시제품 인용(원문 재확인 전) |
| `attack-t1550-004` | MITRE ATT&CK T1550.004 Web Session Cookie | 시제품 인용(원문 재확인 전) |
| `oidc-core` | OpenID Connect Core 1.0 — 1장, 2장, 3.1.3.7절 | 시제품 인용(원문 재확인 전) |

시제품 인용 출처는 S01을 쓸 때 원문을 열어 확인하고 상태를 고친다.
