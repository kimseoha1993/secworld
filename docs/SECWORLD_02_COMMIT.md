# 커밋 메시지

## 1. 형식

```
<type>(<scope>): <설명>

<본문 — 선택>

<꼬리말 — 선택>
```

- 제목과 본문, 본문과 꼬리말 사이에는 빈 줄을 하나 둔다
- `(<scope>)`는 생략할 수 있다

## 2. type

| type | 쓰는 때 |
|---|---|
| `feat` | 화면이나 기능을 더할 때 |
| `fix` | 잘못 동작하던 것을 고칠 때 |
| `docs` | `docs/`, README 등 문서만 바꿀 때 |
| `content` | `content/`의 학습 내용·구성요소 데이터만 바꿀 때 |
| `refactor` | 동작은 그대로 두고 코드 구조를 바꿀 때 |
| `style` | CSS·화면 꾸밈만 바꿀 때 |
| `build` | 의존성, Vite 설정, 배포 설정을 바꿀 때 |
| `test` | 검사 스크립트(`scripts/`)를 바꿀 때 |
| `chore` | 위 어디에도 들지 않는 정리 작업 |
| `revert` | 이전 커밋을 되돌릴 때 |

- 여러 종류가 섞이면 가장 큰 변경의 type을 쓰고, 나머지는 본문에 적는다
- `content`는 Conventional Commits 관례 목록에 없는, 이 저장소만의 type이다. 학습 내용 수정이 잦아 코드 변경과 구분하려고 둔다

## 3. scope

선택. 바뀐 곳을 한 단어로 쓴다.

| scope | 대상 |
|---|---|
| `map` | `src/map/` |
| `panel` | `src/panel/` |
| `search` | 검색 |
| `toc` | 목차 서랍 |
| `progress` | 진행 기록 |
| `world` | 구성요소·연결 (`content/world.js`, `01_WORLD`) |
| `s01` 등 | 학습 단위 하나 (`content/units/`, 단위 문서) |

## 4. 제목

- **한국어로 쓴다**
- 50자 안팎, 최대 72자
- 끝에 마침표를 찍지 않는다
- **명사형으로 끝낸다.** "검색 추가", "시트 높이 계산 수정"처럼 쓴다. "추가했습니다", "추가함"으로 끝내지 않는다
  - 영어 관례의 명령형("add search")에 해당하는 형태다. "이 커밋을 적용하면 ___가 된다"의 빈칸에 들어가게 쓴다

## 5. 본문

- 선택. 제목만으로 충분하면 쓰지 않는다
- **무엇을, 왜 바꿨는지**를 쓴다. 어떻게 바꿨는지는 diff에 있으므로 반복하지 않는다
- 한 줄은 72자 안팎에서 줄을 바꾼다
- 여러 항목은 `- `로 나열해도 된다

## 6. 꼬리말

- 호환이 깨지는 변경(저장된 진행 기록 형식이 바뀌는 등): 제목의 type 뒤에 `!`를 붙이거나(`feat(progress)!: …`), 꼬리말에 `BREAKING CHANGE: <설명>`을 쓴다
- 공동 작성자 표기(`Co-authored-by`)는 쓰지 않는다. 작업자가 한 명이다

## 7. 예

```
feat(search): 구성요소·주제·카드 검색 추가
```

```
fix(panel): 모바일 시트에서 테스트 입력 시 높이가 내려가는 문제 수정

테스트 카드로 넘어갈 때 전체 높이로 올렸다가, 입력창에 포커스가
들어가면서 창 높이가 바뀌어 반 높이로 되돌아가던 것을 막는다.
```

```
content(s01): 1단계 본문의 기관 이름을 지도 이름에 맞춤
```

## 8. 템플릿

저장소 루트의 `.gitmessage`가 이 형식의 빈 틀이다. 이 저장소에서 `git commit`을 메시지 없이 실행하면 편집기에 틀이 채워진다. 설정은 저장소 전용이다(`git config commit.template .gitmessage`).
